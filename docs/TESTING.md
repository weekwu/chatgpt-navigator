## 安装后真实网站验收

1. 加载 dist，刷新现有的普通对话；比对用户问题数量与顺序，悬停检查文本。
2. 跳到中间一问，再手动滚动；确认提问不被顶部栏遮挡、高亮正确。
3. 连续发送消息，等待回答流式输出；确认导航新增、输入框与原按钮不受影响。
4. 在两个聊天、一个 Projects 聊天之间切换，使用浏览器后退。
5. 打开长对话并向上加载历史；观察节点增加；如果消息回收，确认状态提示准确。
6. 切换浅/深色，改变窗口宽度；检查与右侧原生按钮的位置关系。
7. 在扩展管理页禁用、启用并刷新；确认无重复入口。

若某项失败，应记录不包含聊天正文的结构特征（属性名称、滚动容器层次、遮挡区域尺寸），优先修复 DOM/滚动适配层，不上传聊天内容。

## 1.0.2 缓存页面切换修复

2026-10-21，用户反馈切换到普通聊天后导航再次消失。通过 Elements 面板确认同一 DOM 中保留了三个带有 `data-thread-find-target="conversation"` 的对话容器，第一个属于已缓存的其他聊天。1.0.1 只取第一个匹配项，错误观察了隐藏旧对话。

修复：从地址解析当前对话 ID，匹配 `data-chatgpt-conversation-selection-target` 并检查可见性；找不到目的容器时等待挂载，绝不回退到身份明确但属于其他对话的容器。旧结构没有路由标识时，按可见性降级。另修复了 React 在路由事件前复用节点身份可能导致新消息被错误排除的问题。

增加四个合成 DOM 用例：三个保留容器中的项目/普通对话反复切换三轮；路由先改变、目标容器延迟挂载和解除 hidden；旧结构多个 main 中仅选择可见页面；路由事件前复用消息节点。

最新 `npm test`：**31 项通过，0 失败，33.1 秒**。TypeScript 严格检查和生产构建通过。最新机器可读结果在本地 `test-results/results.json` 中，未纳入版本库。

真实 Chrome 验证：重新加载 1.0.2 并刷新一次以应用新代码，此后在同一标签页执行普通聊天 → 点击 Projects 聊天 → 浏览器后退回普通聊天。两次切换都没有手动刷新，导航自动显示；普通聊天展开目录显示当前已加载的 5 条提问。验证结束保留该目录展开，未保存聊天正文或真实截图到项目中。
