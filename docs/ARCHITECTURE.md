# 架构与实现原理

## 设计决策

使用无框架的 TypeScript 内容脚本，打包为一个 IIFE。生产构建没有运行时 npm 依赖，没有服务工作线程、弹窗、设置页或存储权限。简单产品保持单标签页生命周期，减少容易失效的跨上下文状态。

界面用 Shadow DOM 隔离。宿主覆盖视口但不接受指针事件，只有导航按钮、目录和提示层接受事件。不会改写 ChatGPT 的布局、history 方法、输入框、消息节点或页面 CSS。宿主层级为 1000，让常规页面弹窗仍可显示在更高层。

## 消息识别

扫描优先限定在当前路由 ID 匹配的 `[data-chatgpt-conversation-selection-target]`，其次使用可见的 `[data-thread-find-target="conversation"]` / `[data-thread-user-message-navigation-content="true"]`，最后降级到可见的 `main` / `[role=main]` / `#thread`。ChatGPT 会保留多个缓存对话容器，不能按第一个 DOM 匹配项选择；目的容器尚未挂载时等待，不索引旧聊天。优先识别 `data-message-author-role="user"`，兼容 `data-author="user"`、`data-role="user"`，以及 2026 app-shell 的 `[data-chatgpt-search-unit-key$=":user"]`。新版身份使用 `data-chatgpt-search-message-ids` 或 `data-turn-key`；不用带有 fallback 序号的搜索单元键作为稳定身份。再检查具有 conversation-turn 语义的 article：明确 user 元数据，或准确匹配的发言人标题。新版 `data-turn-key` 包含整轮 Q&A，语义降级时只选择准确的隐藏发言人 h4/h5/h6 标题紧邻的用户内容，避免将助手回复一起索引。普通 article 的正文、助手文本或任意按钮文案不被猜测成用户提问。

根据 DOM 顺序排列，排除隐藏区域和对话框。稳定 ID 优先使用 `data-message-id`，其次为 turn ID；没有稳定标识则通过 WeakMap 给当前 DOM 节点分配临时身份。不会使用容易因历史插入而改变的 turn 序号或消息文本作为永久身份。

索引保留 `key / element / title / preview / search`，仅存内存。增量变更时只重新提取脏消息和新消息的文本。相同 ID 重渲染会替换对应元素引用；稳定 ID 被回收后保留不可用目录项。未知历史不计数，不请求内部 API，不尝试模拟滚动加载数百次来获取全部历史。

纯文本从消息克隆中提取，不改变原 DOM。移除交互按钮、隐藏内容，代码块替换为标记，清理常见 Markdown 符号，保留短预览与更完整的搜索文本。摘要上限 92 个 JS 字符，预览上限 1400；目录视觉上再限制两行。聊天内容始终通过 `textContent` 写入。

## 更新与生命周期

1. 一个轻量生命周期观察器关注 main 的挂载/替换以及扩展宿主是否被移除。main 仍连接时不做全页面选择器扫描。
2. 一个局部 MutationObserver 观察 main。用户消息的字符/结构/身份变更才触发 100ms 合并更新；助手流式输出只使几何缓存失效，不提取全部消息文本、不重建目录。
3. 使用 Navigation API 的 `currententrychange`、`popstate` 等检测路由，并有每 800ms 仅检查 URL/上下文的兼容轮询。不劫持页面的 history，兼容 Chrome 内容脚本的隔离世界。
4. 聊天路由切换清空目录并排除过渡期间仍挂载的上一聊天 DOM；普通/Projects 新聊天初次获得 `/c/id` 路由时，保留同作用域内已挂载的首条提问；短暂观察过渡状态，若实际加载的是不同聊天则丢弃草稿索引。Projects 既有聊天的识别不依赖特定路径格式。
5. 重新注入先销毁旧实例。销毁时断开所有观察器、取消动画帧/定时器、移除事件监听、释放索引和 UI；`pagehide` 的 BFCache 情况保留实例以便恢复。禁用/重新加载导致扩展上下文失效时，轮询负责移除旧实例。

## 实际滚动容器与定位

从目标用户节点向上查找，选择首个 `overflow-y` 允许滚动且有实际溢出内容的祖先。找不到时使用 window。运行中容器布局改变会重新绑定，非初始时硬编码。

定位计算为：

```text
目标滚动值 = 当前 scrollTop + 消息视口 top - 滚动容器视口 top - 顶部保留空间
```

容器 border、`scroll-padding-top` 和可见的 fixed/sticky 顶栏纳入计算。顶部遮挡采用少量固定采样点的 `elementFromPoint` + 受限祖先检查，不扫描整个页面。目标值限制在合法滚动区间。减少动态效果模式直接滚动，其他情况平滑滚动。

跳转结束后复测元素位置，对图片/流式布局引发的偏移最多校正三次。用户滚轮、触摸或滚动键取消校正。目标已断开或没有渲染框时，直接提示不可定位。无法在有限校正内稳定到达时提示重试，不显示虚假成功状态。

滚动状态维护已测量的位置数组。scroll 回调只排队一个动画帧，并对缓存做二分定位；不读消息文本，不做 DOM 查询。IntersectionObserver 和 ResizeObserver 负责触发位置缓存重测。页面流式布局、图片 load 和 resize 也会使缓存失效。到达底部时允许可见的最后一问高亮，处理最后一轮无法对齐顶部的情形。

## 性能范围

用户结构变化时，重新查询 main 范围内的用户节点、合并顺序。提取文本仅处理新增/改变的消息。初始排序、去重和历史合并有简单的数组比较，适用于数百问规模；没有为无限数量历史做持久化或复杂虚拟列表。

横条最小点击高度 22px，数量增大时在最大 56vh / 540px 的内部轨道滚动，避免把上百个点击目标压成难以命中的像素点。目录同样内部滚动。默认轨道预览无远程字体、图片或其他请求。

## 兼容边界

无法保证未公开的 ChatGPT DOM 永不变化。多层嵌套且同时滚动的特殊布局、非标准遮挡层、封闭 Shadow DOM 或 Canvas 消息、身份完全不稳定的虚拟节点需要进一步适配。若不同分支被回收成缺失 DOM，无法只凭 DOM 自动断言哪些消息仍属于当前分支；因此保守标记未加载/可能不在分支。

1.0.1 已在真实登录态 Projects 对话中验证显示、展开目录和定位；另外 27 项真实扩展自动化通过，含从线上结构抽象出的三个无聊天内容回归用例。仍不能证明 ChatGPT 所有实验版本均适用。

1.0.2 补充：切换时的旧消息排除保存索引时的身份，而不是读取可能已被 React 复用的新节点身份；没有稳定 ID 时才比对先前提取文本。真实页面验证普通聊天 → Projects → 浏览器后退返回普通聊天，均无需刷新，导航自动恢复。31 项自动化通过，含三个缓存容器反复切换三轮的回归测试。
